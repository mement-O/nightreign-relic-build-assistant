# v1.1.0 言語と設定の管理

## 表示と判定の分離

- `locale-en.js` はUI文言、`names.en.json` は効果・遺物の英語名称を持つ。
- `i18n.js` は描画済みの表示と補助属性だけを翻訳する。元の日本語を保持し、分類UIが表示名を読む箇所は `sourceText` で元の名称を取得する。
- 正式マスタ・検索キー・入力値・並び順は翻訳しない。言語切替は検索や画面全体の再描画を起動しないため、実行中の検索、選択状態、入力途中の名前を保持する。
- `translate="no"` のユーザー入力名とライセンス原文は変更しない。未収録の名称は日本語を維持する。
- 英語名称のランクは正式日本語マスタに合わせる。英語スナップショット内の古いランクを採用しない。例：Effect ID 6001400 は正式マスタの +3 を表示する。

## 保存キー

| 対象 | 保存する識別子 |
| --- | --- |
| 言語 | `nrba_language_v1` の `ja` / `en` |
| 評価対象外 | `ignore:<代表Effect ID>` |
| デメリット除外 | `demerit:<代表Effect ID>` |
| 検索条件 | 正式マスタの `masterKey` と既存のランク識別子 |
| メリット除外 | 正式マスタキー・ランク・通常／深層の既存複合キー |
| マイセット | プレイヤー・セーブ枠・キャラクター・器・順序付き遺物情報の既存キー |

`masterKey` に日本語を含むものも固定識別子として扱い、英訳や表示文言の変更で書き換えない。保存された条件・メリット除外の `label` は表示用の日本語原文であり、識別判定には使わない。

`effect-identities.json` の `ignoreById` は同じEffectGroupまたは同じ基底効果名のIDをまとめる。ランク違い・通常／深層をまとめて評価対象外にする仕様を維持する。`demeritById` は従来の同一日本語効果名の集合を固定したもの。これらは表示言語や読み込んだセーブ内容から実行時に生成しない。

**既存の代表IDは変更しない。** マスタ追加時は該当ファミリーに新IDを追記する。新しいファミリーだけ新キーを発行する。名称変更や小さいIDの追加を理由に代表IDを再採番しない。分割・統合が必要な場合は保存設定の明示的な移行を用意する。

## 旧設定の移行

既存localStorageキーを継続使用し、状態形式をv5へ更新する。v2〜v4も読み込める。

- `legacyIgnore`：旧 `g:EffectGroup` / `n:日本語基底名` → 固定ID。
- `legacyDemerit`：旧日本語効果名 → 固定ID。旧 `names` 配列から新 `keys` 配列へ移行。
- 未知の旧キーは削除せず保持。既存の検索条件・メリット除外・マイセットの保存形式は維持。
- 言語切替は除外設定をリセットしない。検索条件変更時の除外リセットは従来どおり。
- 旧日本語版はv5形式を読めないため、旧版へ戻す場合は保存設定も移行前へ戻す必要がある。

- 正式マスタのランクが英語でも保持され、日本語／英語どちらの語句でも絞り込めること。
- 指定6条件の実セーブ由来データで高速50件・100件、全件1005件を確認。既存のメリット除外と無効な左側優先効果の扱いも回帰確認。

## v1.1.3 表示の補完

改行を含む深層効果、評価対象外のスキル使用回数、デメリットなし・判定不能・日時不明、最適化の元構成、セーブ解析エラーの英語表示を補完。プリセット選択欄では、自動生成する名称・日時のみ翻訳し、利用者の名前は保持する。言語変更時には選択中のプリセットを維持して選択欄の表示を更新する。

10キャラクターの検索条件・評価対象外・追加候補・メリット候補、検索結果詳細、最適化、マイセット、エラー文言を画面生成テストで再点検。意図した言語ボタン以外の未翻訳は検出されなかった。日英往復で「名称なし」「検索」という利用者の名前とプリセットの選択位置が変わらないことも検証した。ブラウザでは評価対象外のスキル使用回数の英語表示と日本語への復帰を確認した。
